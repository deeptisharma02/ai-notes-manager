# Setup & Run Guide — AI Notes Manager

Step-by-step instructions to run the project locally with Docker.

---

## 1. Prerequisites

- **Docker** and **Docker Compose** installed and running
- Free ports: **8000** (app), **3307** (MySQL), **6379** (Redis)
- (Optional) An **OpenAI API key** for real semantic search & summaries

No local PHP, Composer, MySQL, or Redis is required — everything runs in Docker.

---

## 2. Quick start

From the project root (`c:\php`), run these four commands:

```bash
# 1. Create the environment file
cp .env.example .env

# 2. Build and start all containers (app + MySQL + Redis)
docker compose up --build -d

# 3. Generate the application key
docker compose exec app php artisan key:generate

# 4. Create the database tables
docker compose exec app php artisan migrate --force
```

That's it. Open:

- **App UI:** http://localhost:8000
- **API docs (Swagger):** http://localhost:8000/api/docs

> On Windows, run these in **PowerShell**. If `cp` is not recognized, use:
> `Copy-Item .env.example .env`

---

## 3. What each step does

| Step | Command | Purpose |
|------|---------|---------|
| 1 | `cp .env.example .env` | Creates config (already set for Docker: MySQL host `db`, Redis host `redis`) |
| 2 | `docker compose up --build -d` | Builds the PHP 8.4 image and starts app, MySQL, and Redis in the background |
| 3 | `php artisan key:generate` | Sets Laravel's `APP_KEY` (required) |
| 4 | `php artisan migrate --force` | Creates the `notes` and supporting tables |

---

## 4. Enable real AI (optional)

By default the app works without any API key:
- Summaries use a local extractive fallback
- Search uses keyword matching

To enable **OpenAI** semantic search and summaries:

1. Open `.env` and set your key:
   ```
   OPENAI_API_KEY=sk-your-key-here
   ```
2. Restart the app:
   ```bash
   docker compose restart app
   ```

Now summaries are generated by OpenAI and search returns `source: semantic`.

---

## 5. Running tests

```bash
docker compose exec app php artisan test
```

Tests run on an isolated in-memory SQLite database (configured in `phpunit.xml`),
so they don't touch MySQL or Redis.

---

## 6. Useful commands

```bash
# View running containers
docker compose ps

# Tail application logs
docker compose logs -f app

# Open a shell inside the app container
docker compose exec app bash

# Stop everything
docker compose down

# Stop and also remove the database volume (fresh start)
docker compose down -v
```

## 7. Troubleshooting

**Port already in use (e.g. 8000 / 3307 / 6379)**
Another service is using that port. Stop it, or change the host port in
`docker-compose.yml` (e.g. `'8001:8000'`) and use the new port.

**Code changes don't show up**
For performance, OPcache runs with `validate_timestamps=0`. After editing PHP
files, reload the cache:
```bash
docker compose restart app
```
(Frontend/Blade changes are picked up immediately; this only applies to PHP code.)

**`migrate` fails right after `up`**
MySQL takes a few seconds to become healthy on first boot. Wait ~15–20s and
re-run the migrate command.

**Reset the database**
```bash
docker compose exec app php artisan migrate:fresh --force
```
